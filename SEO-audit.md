# Technical SEO audit — Omar Agha portfolio

## Executive summary

The [English homepage](https://omar-agha.is-a.dev/) and [Arabic homepage](https://omar-agha.is-a.dev/ar/) are live on the custom domain and return HTTP `200`. Both initial responses contain localized titles and descriptions, but their bodies contain only an empty Vue mount point. Crawlers must execute JavaScript to discover the portfolio content, navigation, and language switcher.

**Recommendation:** Prerender the two locale pages at build time and keep Vue for interactions. The site has two stable routes backed by local JSON, so static generation fits GitHub Pages without a server or framework migration. First, make the custom-domain configuration reproducible and publish canonical, language-alternate, and social metadata.

**Audit scope:** Repository inspection, a production build of commit `701ed90` in a temporary directory, Chromium testing, and public HTTP checks. No site changes were made during the audit. Search Console indexing and real-user Core Web Vitals were outside the available evidence. File references below are relative to the repository.

## Current architecture and strengths

- **Two real locale URLs.** Vite emits `index.html` and `ar/index.html`. The Vue history router selects the locale from the path. The initial documents declare `lang="en" dir="ltr"` and `lang="ar" dir="rtl"`. Testing confirmed direct loads under a GitHub Pages-style subpath and language switching with the query string and section fragment preserved. [Vite configuration](vite.config.ts#L18), [Vue router](src/router/index.ts#L5), [language switcher](src/components/SiteHeader.vue#L87)
- **Localized metadata already ships in the response.** Each locale has its own title, meta description, Open Graph title and description, and `og:locale`. Both pages have `og:type=website`. The titles identify the person and role, and the descriptions communicate the specialization. Neither live response had a robots meta directive or an `X-Robots-Tag` header. [Build-time metadata](vite.config.ts#L29), [English SEO data](src/data/en.json#L70), [Arabic SEO data](src/data/ar.json#L70)
- **Good semantics after rendering.** Each locale rendered one H1, six section H2s, and H3s for entries. The site uses `header`, `nav`, `main`, `section`, `article`, and `footer`, with a skip link and real section anchors. Testing confirmed mobile menu focus, Escape dismissal, and focus restoration after closing a project drawer. The About portrait has localized alt text, the repeated brand photo has an appropriate empty alt, and decorative artwork is hidden from assistive technology. [Page landmarks](src/views/PortfolioView.vue#L235), [About portrait](src/components/AboutPortrait.vue#L103), [drawer focus handling](src/components/ProjectDrawer.vue#L36)

## Findings and recommendations

| Severity | Finding | Recommendation and trade-off |
| --- | --- | --- |
| **High** | **The initial HTML contains zero body text and zero links.** This was confirmed with JavaScript disabled on both built pages. Google can render JavaScript, but discovery and indexing depend on that rendering succeeding. Crawlers without JavaScript see an empty portfolio. | Prerender both pages from the existing Vue templates and JSON, then hydrate the interactive parts. This adds a build step and hydration checks while keeping the deployment static. [Vue entry point](src/main.ts#L3), [Google’s JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) |
| **High** | **Canonical and language-alternate signals are missing.** Both `/index.html` and `/ar/index.html` return `200` with the same content as their directory URLs. The switcher has `hreflang` on a rendered link, but neither document declares reciprocal alternates in its head. | Emit absolute, self-referencing canonicals for `/` and `/ar/`, plus reciprocal `en` and `ar` alternates on both pages. Use `x-default` for `/` if English is the intended fallback. Use directory URLs consistently in links, metadata, and the sitemap. Canonicals can consolidate aliases without requiring server redirect rules. [Router aliases](src/router/index.ts#L7), [Google’s canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [Google’s localized URL guidance](https://developers.google.com/search/docs/specialty/international/localized-versions) |
| **High** | **The live custom domain works, but the deploy script does not carry its configuration forward.** The default GitHub Pages URLs redirect to the custom domain, and `CNAME` exists on `gh-pages`. The source tree and generated output lack it, and `gh-pages -d dist` defaults to removing published files absent from the new output. A routine deploy could remove the file the current branch-based setup relies on. | Make the domain part of the publish step through `public/CNAME` or the deploy command’s `--cname` option. Document the publishing source and verify the custom-domain redirects after deployment. An Actions migration is optional. [Deploy scripts](package.json#L15), [published CNAME](https://raw.githubusercontent.com/Omar-Agha/portfolio/gh-pages/CNAME), [GitHub Pages custom-domain guidance](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) |
| **Medium** | **Social cards are incomplete.** Neither initial response includes `og:url`, `og:image`, or Twitter Card tags. Both locale files point to `/images/og-cover.webp`, which returns `404` live. After Vue runs, the asset check omits `og:image` and the only Twitter tag is `twitter:card=summary`. | Publish a valid, absolute share-image URL, `og:url`, image alt text, and Twitter Card fields in the initial localized HTML. A shared image is sufficient if it works in both languages. Use one metadata generator so direct loads and client-side locale switches produce consistent values. [Runtime metadata](src/views/PortfolioView.vue#L206), [Open Graph protocol](https://ogp.me/) |
| **Medium** | **Discovery and error handling rely on defaults.** Live `/robots.txt` and `/sitemap.xml` return `404`. Their absence does not block indexing. Unknown paths correctly return `404` on GitHub Pages, and `/ar` redirects to `/ar/`. The client catch-all redirects unknown routes to English after the app loads. | Publish a sitemap with the two canonical URLs and reference it from a root-level `robots.txt`. Keep CSS and JS crawlable. A small bilingual `404.html` would improve recovery while preserving HTTP `404`. Avoid a blanket homepage fallback that serves `200` for missing pages. [Router fallback](src/router/index.ts#L20), [Google’s sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [GitHub Pages 404 guidance](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site) |
| **Medium** | **The strongest project details are behind buttons.** Cards expose titles and summaries after rendering. Detailed descriptions, achievements, and some outbound links exist only after opening a drawer. Prerendering the current page would still leave that content behind an interaction. Engineering Lab’s GitHub links are already real anchors on the cards. | Put the most important case-study evidence and links in visible content for priority projects. Keep the drawers for extended detail. Add dedicated project URLs only if there is enough content and a reason to index them independently. [Featured Work cards](src/components/FeaturedWorkCard.vue#L14), [Lab links](src/components/EngineeringLab.vue#L101), [drawer content](src/components/ProjectDrawer.vue#L142) |
| **Low** | **A few extraction and presentation details need cleanup.** Both templates declare an empty `data:,` favicon even though `/favicon.ico` returns `200`. The split H1 spans concatenate words in DOM text extraction, such as `systemsthat`. Two Lab covers point to missing files and are safely omitted by the asset resolver. | Reference a real favicon and preserve a space between headline spans or let CSS wrap one text node. Resolve the missing cover references if those covers are intended to appear. Review empty alt text on project covers individually and add descriptions where the image conveys information beyond the surrounding copy. [HTML template](index.html#L7), [Hero heading](src/components/HeroSection.vue#L22), [asset resolver](src/content.ts#L146), [Google favicon guidance](https://developers.google.com/search/docs/appearance/favicon-in-search) |

**Critical:** No site-wide availability or indexing blocker was confirmed. Both locale URLs were publicly reachable at the time of the audit.

## Structured data

**Low severity.** Neither page currently emits JSON-LD. Add a `ProfilePage` for each canonical locale URL and point `mainEntity` to the same `Person` identifier. Populate the person from the existing profile data, including Omar Agha’s name, job title, portrait, and GitHub and LinkedIn profiles. The localized pages can carry their own `inLanguage` and descriptions. A `WebSite` node on the custom-domain homepage can provide a consistent site name and connect the pages to the site. Use facts already visible on the portfolio and omit invented dates, ratings, or achievements. Structured data can clarify the entity and does not guarantee a special search result. [Portfolio profile data](src/data/en.json#L97), [Google ProfilePage documentation](https://developers.google.com/search/docs/appearance/structured-data/profile-page), [Google site-name documentation](https://developers.google.com/search/docs/appearance/site-names)

## Performance

| Metric | Measured in the local production build | Interpretation |
| --- | --- | --- |
| **LCP** | Three cold mobile runs per locale at 390px, with 4× CPU slowdown, 150 ms latency, and 1.6 Mbps download. Median **1.50 s English** and **1.74 s Arabic**. The Hero description was the LCP element in all six runs. | The first meaningful paint depends on the JS bundle and Hero entrance. Keep the prerendered heading and description visible immediately, with motion added afterward. |
| **CLS** | No layout-shift entries in the six startup samples. | This is an initial-load observation. The responsive portrait and cover containers already reserve space. Check drawer opening, locale switching, and scrolling separately. |
| **INP** | Field INP was unavailable. Startup produced main-thread long tasks of **283–535 ms**. | The long tasks show startup work. Profile menu, drawer, and language-switch interactions before attributing the cost to Vue, GSAP, or specific components. |

The shared build contains **303 kB of JS and 45 kB of CSS**, or roughly **109 kB and 10 kB gzip**, respectively. Both locales and the page’s animation code load together. The stylesheet blocks first paint, and there are no external font requests in the inspected build. GSAP and ScrollTrigger are used throughout the site, with reduced-motion support and several offscreen pause mechanisms already in place. Profile their startup cost, then consider deferring below-the-fold animation initialization or loading locale data on demand if the trace justifies the extra request on first language switch. The devtools package is a development dependency. [Locale imports](src/content.ts#L1), [Hero entrance](src/components/HeroSection.vue#L43), [font stacks](src/assets/main.css#L20), [Core Web Vitals methodology](https://web.dev/articles/vitals)

The clearest asset savings are in the **1.10 MB, 1254×1254 header avatar displayed at about 38 CSS pixels**. Use a dedicated small avatar asset and reuse it in the footer. The About portrait already selects separate lazy-loaded mobile and desktop WebP files. Drawer covers are loaded on demand, but some are 4000px wide for a drawer capped at 624 CSS pixels. Right-sizing those covers would reduce project-opening transfer and decode costs while keeping the current layout. [Header avatar](src/components/SiteHeader.vue#L59), [avatar dimensions](src/assets/main.css#L111), [responsive About image](src/components/AboutPortrait.vue#L103), [drawer cover](src/components/ProjectDrawer.vue#L142)

## Prioritized roadmap

1. **Protect deployment and establish canonical URLs.** Preserve `CNAME` in the publish step. Generate the canonical, `hreflang`, sitemap, and social tags from one production URL configuration. Fix the missing share image and favicon.
2. **Prerender `/` and `/ar/` from the existing Vue components.** Keep the router, Tailwind, JSON locales, drawers, and interactions. Move browser-only document access behind client lifecycle hooks where necessary. Verify that initial HTML contains meaningful headings, content, and links with JavaScript disabled. [Current browser-dependent URL setup](src/content.ts#L134), [Vue’s static generation guidance](https://vuejs.org/guide/scaling-up/ssr.html)
3. **Make priority case studies discoverable.** Surface their key evidence and useful links in the rendered page, then add `ProfilePage`, `Person`, and `WebSite` JSON-LD.
4. **Measure the result on the live canonical URLs.** Check both pages in Search Console URL Inspection, submit the sitemap, test social previews and the custom-domain redirects, and compare mobile performance before and after resizing the avatar and deferring measured startup bottlenecks.

## Architecture verdict

Keep the Vue application and GitHub Pages. Generate two prerendered locale pages with meaningful initial HTML and hydrate the existing interactions. This addresses the largest crawlability gap while preserving the existing site and deployment model.
